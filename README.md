# QR Menu — interactive restaurant menu (MVP)

Guests scan a QR code on the table and get a dark, card-based menu built for phones: dish photos,
videos that play as they scroll, prep times, badges, chef notes and pairings.

**No build step and no dependencies.** It's plain HTML/CSS/JS, so it hosts free on GitHub Pages, Netlify or Vercel.

## Run locally

```bash
cd ~/Pratham/qr-menu
python3 -m http.server 5173
```

Open <http://localhost:5173/?r=arabico&t=12>. The demo menu is **Arabico Specialty Coffee, Janakpuri**: 86 items across 14 tabs, 19 of them with video. On a desktop browser you'll see a "scan with your phone" screen.
Click **Preview on this screen**, or use your browser's device toolbar.

## URL format

| Part | Example | Meaning |
|---|---|---|
| `r` | `?r=arabico` | Restaurant slug → loads `data/arabico.json` |
| `t` | `&t=12` | Table number shown in the header (optional) |
| `#section` | `#barista-picks` | Opens a specific top tab |
| `preview` | `&preview` | Skips the desktop "use your phone" screen |

Each table's QR code just encodes a URL like `https://<your-site>/?r=arabico&t=12`.

## Adding a restaurant

Copy `data/arabico.json` to `data/<slug>.json` and edit it:

- `name`, `tagline`, `logo` (image URL, or `null` for a monogram), `chef`
- `currency` / `locale` (e.g. `INR` + `en-IN`, `AED` + `en-AE`)
- `theme.primary` / `theme.secondary`: the customer's brand colours. The background always stays black.
- `badges`: badge keys → `{ label, tone: primary | secondary | neutral }`
- `sections`: the **top tabs**, the only navigation. Each is either
  - `type: "tag"`: a curated list (e.g. "Most loved at {name}", "Chef's Picks") matching dishes whose `tags` contain `match`, or
  - `type: "category"`: dishes whose `category` equals `match`.
  `{name}` in a label is replaced by the restaurant name.
- `dishes`: `id, name, category, price, prepTime (min), image, video?, description, tags, badges,
  diet {veg, egg, vegan, gf}, spice (0–3), kcal?, story?, chefNote?, pairings?, allergens?`.
  A pairing can point to another dish with `dishId`, which makes it tappable.

The demo data is generated by `tools/build-demo-data.py`. You can also edit the JSON directly.
Optional: a section can have `order: [dishId, …]` to set the order of its dishes.

> **About the Arabico demo data:** item names, sections and prices follow Arabico's public Zomato listing (Nov 2026).
> Most descriptions, prep times, badges, kcal and pairings are **placeholders**. Confirm them with the owner before going live.

Colours, logo and branding are set per restaurant in its JSON file. In a later phase they'll be editable only by the owner, from the admin dashboard. Guests can't change them.

## How video playback works

- A video's source loads only when it's ~400px from the screen, which saves guests' mobile data.
- The **topmost video that is at least 60% on screen** auto-plays, muted, and every other video pauses.
- **Touching a video** (or hovering it with a mouse) makes it the one that plays.
- Guests with *reduce motion* or *data saver* turned on get no autoplay. Videos play only when touched.
- The speaker button turns sound on. Tapping a card opens a detail sheet, which closes with ✕, a swipe down, or the phone's back button.

## Deploy for free (GitHub Pages)

1. Create a GitHub repo and push this folder.
2. Repo → **Settings → Pages** → Source: `Deploy from a branch`, branch `main`, folder `/ (root)`.
3. Your menu will be at `https://<user>.github.io/<repo>/?r=arabico&t=12`.

The demo media is hot-linked from free sources (Unsplash photos, Mixkit videos). Real restaurants should
upload their own media. See `TODO.md`.
